# lob-lab

How much of a market maker's backtested P&L is an artefact of assuming fill-at-touch,
measured on real Deribit BTC-PERPETUAL data, and how much of the inventory-skew
advantage measured on synthetic paths in `vol-lab` survives a queue-aware fill model.

- The question and the hypotheses: `docs/spec.md`.
- The hypotheses, fixed before any data was collected: `docs/preregistration.md`.

## Status

Work in progress. Results are not in yet, so this README carries no numbers. When it
does, every number carries an uncertainty and the command that regenerates it.

## How the book is checked

The obvious check is the exchange's own `quote` channel, and it is the wrong one. That
feed publishes when the best price changes; the book feed is aggregated to 100ms. On BTC
the best moves several ticks inside 100ms, so the two describe different moments and
disagree about 45% of the time while the book is exactly right.

The check that decides carries its own sequence number. Deribit's REST snapshot reports
the `change_id` it was taken at, and that is the same sequence the book channel advances,
so replaying to that exact id compares like with like. Measured on four minutes of live
data on 2026-09-23: 24 snapshots reached, 3 comparable at an exact id, **3 identical, 0
different**, and 21 straddling two aggregated updates.

    make record     # writes data/, with a REST snapshot every 30s
    make verify     # reports drift, then the decisive comparison

## Limitations, stated up front

- The `raw` book interval requires an authenticated Deribit connection. This repository
  uses the public `100ms` interval, which aggregates changes inside each interval, so
  queue position between two snapshots is inferred rather than observed.
- No market data is committed here. Tests run on synthetic fixtures generated by the
  repository itself.
- The REST comparison only lands on an exact `change_id` when the aggregated feed happens
  to end a 100ms window on that id, which was 3 times in 24 here. A `raw` subscription,
  which needs an authenticated connection, would make every snapshot comparable.
